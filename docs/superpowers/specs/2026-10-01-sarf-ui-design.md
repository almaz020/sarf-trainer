# Этап 2: UI конструктора и проверки (сарф-тренажёр)

Источник требований: `TZ_sarf_trainer.md` (п. 8, 9, 11, 12, этап 2). Здесь только решения по неоднозначностям и план. Всё, чего нет здесь и в ТЗ, не реализуется. Движок этапа 1 (`src/engine`) используется как есть и не меняется.

## Объём

Экран **одного задания**: конструктор ответа, проверка с двумя попытками, показ правильной формы, ссылка на словарь и ссылка на правило. Два гейта запуска. Автопереход через 1 с, выбор случайного глагола, 9 заданий подряд, счётчик и сообщения хода относятся к этапу 3.

## Принятые решения

1. **Стек:** Vite, React, TypeScript, Vitest, `@fontsource/amiri` (шрифт Amiri). Для тестов UI добавляются `@testing-library/react`, `@testing-library/user-event`, `jsdom` (в ТЗ их нет, добавление утверждено владельцем).
2. **Граница этапов 2/3:** этап 2 = одно задание. Компонент отдаёт результат колбэком; таймер 1 с и ход тренировки делает этап 3.
3. **Пустой ответ не засчитывается:** «Проверить» неактивна при пустом ответе, попытка не тратится.
4. **После «Стереть последнюю»** выбирается новый последний слот; если слотов нет, выбора нет. Огласовка и шадда без выбранного слота ничего не делают.
5. **Данные:** тестовые фикстуры только в тестах и в dev-режиме `?demo`, помечены `TEST-…`. В продакшен-сборку не попадают. Реальные глаголы остаются `verified: false` (правило CLAUDE.md), поэтому реальное задание появится, когда владелец поставит `verified: true` и заполнит источники.
6. **Гейты** (оба в `App`, по ТЗ п. 7 и п. 8):
   - есть записи `validateParadigm()` → тренировка не запускается, показан список id правил без ссылки;
   - нет проверенных глаголов (после `filterVerbs`) → сообщение «Нет проверенных глаголов в verbs.json».
   При пройденных гейтах показывается задание: первый проверенный глагол × `hum`.
7. **Ссылки:** показывается первый источник с `role: "primary"`. Словарь: «`book`, مادة `entry`, т. `volume`, с. `page`». Правило: «`book`, `section`, с. `page`». Пустые части опускаются. Издание не выводится. Только ссылка, текст правила не показывается.
8. **Модель данных не меняется.** URL найденных источников хранятся только в `docs/sources-research.md`.
9. **Палитра букв: буквы корня + ت ن و ا م, без дубликатов.** Буква م добавлена владельцем: в п. 8 ТЗ её нет, но без неё форма `antum` (ـتُمْ) не собирается для глаголов без م в корне. В ТЗ п. 8 список букв нужно поправить.

## Модули

Логика без React (TDD):

- `src/ui/builder.ts`: `State { slots: Slot[]; selected: number | null }` и чистый редьюсер действий: `addLetter`, `select`, `setHaraka` (замена; повтор той же снимает), `toggleShadda`, `clearMarks` (огласовка и шадда), `eraseLast`, `clearAll`.
- `src/ui/attempt.ts`: автомат проверки. Фазы: ответ → неверно (1-я попытка) → ответ → показан правильный (2-я неверно) / верно. Сравнение только `slotsEqual`.
- `src/ui/refs.ts`: `formatDictionaryRef`, `formatRuleRef`.
- `src/ui/pronouns.ts`: арабские названия и русские описания из п. 4 ТЗ.

React:

- `TrainerScreen` (`verb`, `pronoun`, `onResult`, `onNext`): ряд плиток справа налево, превью слитным письмом (`slotsToString`), палитра букв (R1, R2, R3 + ت ن و ا без дубликатов), палитра знаков (фатха, дамма, касра, сукун, шадда, «убрать знак»), кнопки «Стереть последнюю», «Очистить», «Проверить», блоки ссылок. RTL, Amiri, 360 px и ПК.
- `App`: гейты и задание.

## Тесты

- `builder.test.ts`, `attempt.test.ts`, `refs.test.ts`: поведение п. 8 ТЗ, пустые части ссылок, одна ошибка в знаке не засчитывается.
- Компонентные тесты `TrainerScreen` (Testing Library): сборка формы кликами, верно/1-я неверно/2-я неверно, ссылки появляются при показе ответа, «Проверить» неактивна при пустом ответе.
- Тесты `App`: оба гейта.
- Визуально: dev-сервер, снимки на 360 px и на ПК, проверка наложения огласовок.
- После изменений в `src/engine` (их не планируется) `npm test` и показ результата.
